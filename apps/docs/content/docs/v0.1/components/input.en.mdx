## Import

```tsx
import { Input } from '@akhatmirzo/ui';
```

## When to use

- **For short, single-line values** — names, emails, search, amounts. For multi-line text, use
  [`Textarea`](./textarea.mdx).
- **Always inside a [`Field`](./field.mdx)** — the label, hint and error get wired up for you. For
  a field without a visible label (like search), pass `aria-label`.
- **For strict formats** like phone numbers, card numbers and dates,
  [`MaskedInput`](./masked-input.mdx) is a better fit.
- **A `placeholder` is not a label** — it disappears as soon as you type. Use it for an example
  value: "90 123 45 67".

## Sizes

32, 40 (default) and 48px — the same as `Button`, so they line up in a row.

## Icons, prefix and suffix

`leftIcon` / `rightIcon` are decorative icons (`aria-hidden`). `prefix` / `suffix` are fixed
text inside the field, set off by a divider: a country code, a currency, a domain.

<ComponentPreview name="input/addons" />

## Clearing (`clearable`)

With `clearable`, a ✕ button appears whenever the field has a value. `Esc` clears it too. Clearing
fires a regular `input` event, so `onChange` runs in controlled mode, followed by `onClear`.

## Props

`Input` accepts every other `<input>` attribute (`type`, `name`, `placeholder`, `inputMode`,
`autoComplete`, `onChange` ...), and `ref` points to the inner `<input>`. `className` goes to the
outer container; use `inputClassName` for the inner element.

### Data attributes

Set on the outer container (`data-slot="input"`):

| Attribute       | Value                   |
| --------------- | ----------------------- |
| `data-size`     | `sm` · `md` · `lg`      |
| `data-invalid`  | Present when invalid    |
| `data-disabled` | Present when `disabled` |
| `data-readonly` | Present when `readOnly` |

## Accessibility

- **Native `<input>`** — browser autofill, validation and keyboard behavior all keep working.
- **With Field**, `id`, `aria-describedby`, `aria-invalid` and `aria-required` are wired up
  automatically.
- **The focus ring** lives on the container (`:focus-within`), so icons and prefixes stay inside
  the ring.
- **`Esc`** clears the value (only with `clearable` and a non-empty field). On an empty field the
  event bubbles up — closing a `Dialog`, for example.
- **The clear button** is not in the `Tab` order (`tabIndex={-1}`); `Esc` covers it from the
  keyboard. The password toggle is focusable and its `aria-label` follows its state.
- **Icons** are `aria-hidden` — if one carries meaning, put it in the label or `aria-label`.
