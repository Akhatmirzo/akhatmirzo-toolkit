## Import

```tsx
import { Badge } from '@akhatmirzo/ui';
```

## When to use

- **To show a status** — "Paid", "Pending", "Cancelled". Match the color to the meaning:
  `success` for done, `warning` for waiting, `danger` for errors or cancellations.
- **Don't rely on color alone.** The text should state the status by itself, so it reads right
  for people who can't tell the colors apart.
- **For filter tags** — `onRemove` adds a ✕ button.
- **It isn't clickable.** A badge is a label; use a [`Button`](./button.mdx) for actions.
- **Keep it short** — one or two words. Long text gets truncated.

## Colors

`color`: `neutral` (default), `primary`, `success`, `warning`, `danger` and `info`. Colors come
from the tokens, so contrast holds in dark mode too.

## Variants

`variant`: `soft` (default) has a light background, `solid` a strong one that draws more
attention, and `outline` a border with colored text.

## Sizes

`sm` is compact, for table rows; `md` is the default.

## Dot

`dot` adds a colored dot on the left — handy for live states like "Online" or "Active".

<ComponentPreview name="badge/dot" />

## Removing

When `onRemove` is set, a ✕ button appears. Make its `aria-label` specific with `labels.remove` —
"Remove Toshkent filter" is clearer than just "Remove".

### Data attributes

On the root element: `data-variant`, `data-color` and `data-size`. `badgeVariants` is also
exported if you need the styles on another element.

## Accessibility

- **Plain text** — a `<span>` whose content screen readers read as is. The dot is `aria-hidden`.
- **The ✕ button** is a real `<button>`: focus it with `Tab`, press it with `Enter` / `Space`. It
  looks 16px but has a larger hit area.
- **After a tag is removed**, move focus yourself — to the next tag or the search field — so it
  doesn't get lost.
