## Import

```tsx
import { TagInput } from '@akhatmirzo/ui';
```

## When to use

- **A list of free-form values** — tags, keywords, skills, several emails or phone numbers.
- **When likely values are known** — pass `suggestions`: a list appears while typing, but users can
  still add their own value.
- **When users must pick only from a list** — use `Combobox` with `multiple`; it doesn't let users
  create new values.
- **For a single value**, use a plain [`Input`](./input.mdx).

## With Field

Inside a [`Field`](./field.mdx) the label points at the inner `<input>`, and the description and
error go into `aria-describedby`. `value` + `onValueChange` is the controlled mode, `defaultValue`
the uncontrolled one.

## Adding and removing

- `Enter` or `,` turns the typed text into a tag (change this with `delimiters`, e.g.
  `['Enter', ',', 'Tab']`). On an empty input `Enter` submits the form as usual.
- Paste: `"a, b, c"` → 3 tags. Text is split on single-character delimiters and, when `Enter` is a
  delimiter, on new lines.
- Duplicates are rejected — the comparison ignores case (allow them with `allowDuplicates`).
- `transform` turns raw text into a tag (default — `trim`).
- Double-click a tag (or press `Enter` / `F2` while it's focused) to edit it in place: `Enter` saves,
  `Esc` cancels, clearing the text removes the tag.

## Suggestions

With `suggestions`, matching options show up while typing. Matching uses `normalizeUz`: Cyrillic and
Latin script and apostrophe variants are treated the same — typing «тош» finds «Toshkent». Tags that
are already added are hidden. Move with `↓` / `↑`, `Enter` adds; when nothing is highlighted,
`Enter` adds the typed text itself.

`maxTags` caps the number of tags. Once the limit is reached the input hides and the container gets
`data-full`.

## Validation

`validate` runs for every new tag: `true` accepts it, `false` shows the default error
(`labels.invalid`), a string shows that string. A rejected tag isn't added, the text stays in the
input, the error appears below it and is announced to screen readers, and the input gets
`aria-invalid`. The error clears on the next change.

<ComponentPreview name="tag-input/validate" align="start" />

<Callout type="info">
  The validation error is separate from the `Field` `error` prop — TagInput renders it itself. Pass
  form-level errors (e.g. "At least one tag is required") through `Field error`.
</Callout>

## Sizes and states

`size` — `sm`, `md` (default), `lg`: the same minimum height as Input (32 / 40 / 48px); the
container grows as tags wrap. In `disabled` and `readOnly` states the ✕ buttons are hidden.

## Forms

With `name`, every tag gets a hidden `<input>` with that name:
`new FormData(form).getAll('tags')` → `['React', 'Vue']`. For PHP-style arrays use
`name="tags[]"`.

## Props

`className` goes to the root container; `ref` and other `<input>` attributes (`placeholder`,
`autoFocus`, `onBlur` ...) go to the inner input.

### Data attributes

| Attribute       | Where     | Value                          |
| --------------- | --------- | ------------------------------ |
| `data-size`     | container | `sm` · `md` · `lg`             |
| `data-full`     | container | present when `maxTags` is hit  |
| `data-invalid`  | container | error (or validation error)    |
| `data-disabled` | container | present when disabled          |
| `data-readonly` | container | present when `readOnly`        |
| `data-slot`     | parts     | `tag-input` · `tag-input-root` |

## Keyboard

| Key                               | Action                                                  |
| --------------------------------- | ------------------------------------------------------- |
| `Enter` / `,`                     | Turn the typed text into a tag                          |
| `Backspace` (empty input)         | Select the last tag; press again to remove it           |
| `←` (at input start)              | Move to the last tag                                    |
| `←` / `→` (on a tag)              | Move between tags; `→` on the last one returns to input |
| `Backspace` / `Delete` (on a tag) | Remove the tag                                          |
| `Enter` / `F2` (on a tag)         | Edit the tag                                            |
| `Esc` (on a tag)                  | Back to the input                                       |
| `↓` / `↑`                         | Move through suggestions (with `suggestions`)           |
| `Esc`                             | Close the suggestion list                               |

## Accessibility

- **List.** Tags live in a `<ul role="list">` — screen readers announce how many there are.
- **Announcements.** Adding and removing are announced in a hidden `aria-live="polite"` region
  ("React qo'shildi", "React olib tashlandi"); customize with `labels.added` / `labels.removed`.
- **Errors.** The validation error is visible text in a live region, linked to the input via
  `aria-invalid` and `aria-describedby`.
- **Suggestions.** With `suggestions` the input is a `role="combobox"` (`aria-expanded`,
  `aria-controls`, `aria-activedescendant`) and the list is a `role="listbox"`. Focus always stays
  in the input.
- **✕ buttons** have `aria-label="React ni olib tashlash"` and a hit area of at least 40px.
- **Tags** are focused with the arrow keys (`tabIndex={-1}`); the ✕ buttons are also reachable with `Tab`.
