## What a version number means

A version has three parts: `MAJOR.MINOR.PATCH`.

| Part    | Example         | From 1.0 on                 | During 0.x                       |
| ------- | --------------- | --------------------------- | -------------------------------- |
| `MAJOR` | `1.4.2 → 2.0.0` | Breaking change             | —                                |
| `MINOR` | `0.1.3 → 0.2.0` | New feature, nothing breaks | **May** contain breaking changes |
| `PATCH` | `0.1.0 → 0.1.1` | Bug fix                     | Bug fixes and small additions    |

### What 0.x means

The library is in its `0.x` phase: the API is mostly settled, but it is still being polished in
real projects. During this phase:

- **Patch** releases (`0.1.0` → `0.1.1`) are safe: bug fixes and additions that don't break
  anything.
- **Minor** releases (`0.1` → `0.2`) may break things: a renamed prop, a new default, a component
  split in two. Every such change is listed in the changelog.
- **1.0.0** comes once the API is stable. After that, breaking changes only land in major
  releases.

<Callout title="How ^0.1.0 behaves">
  `pnpm add` writes `"^0.1.0"` to your `package.json`. In `0.x`, the caret only accepts **patch**
  updates: you get `0.1.5`, but not `0.2.0`. Moving to a minor release that might break things is
  always your call.
</Callout>

### How the packages depend on each other

`@akhatmirzo/ui` takes `core` and `hooks` as regular dependencies and `tokens` as a
**peer dependency** — you install the tokens yourself and import them in your CSS. Upgrade `ui`
and `tokens` together: a new component may rely on a new token.

## Documentation versions

This site keeps one set of docs per **minor** version: `v0.1`, `v0.2` and so on. Patch releases
update the current set. Switch versions with the picker in the sidebar. Pages of an older version
show a banner with a link to the latest one.

## Upgrading

<Steps>
<Step>

### Read the changelog

Go through every entry between your version and the new one. When moving to a new minor release
in `0.x`, read the **Minor Changes** section closely — that's where breaking changes are listed.

</Step>
<Step>

### Upgrade the packages together

Bump every `@akhatmirzo/*` package you use in one command:

```bash
pnpm up "@akhatmirzo/*" --latest
```

With npm: `npm install @akhatmirzo/ui@latest @akhatmirzo/tokens@latest` (and the same for the
others).

</Step>
<Step>

### Check

`tsc --noEmit` points out removed or renamed props. Then open the app and look through the main
screens in both light and dark mode.

</Step>
</Steps>

<Callout type="idea" title="Stick to one version">
  Don't end up with two versions of `@akhatmirzo/ui` in one project (for example, across apps in a
  monorepo). Check with `pnpm why @akhatmirzo/ui`.
</Callout>
