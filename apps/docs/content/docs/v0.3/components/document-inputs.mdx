## Import

```tsx
import {
  BankAccountInput,
  CarPlateInput,
  InnInput,
  PassportInput,
  PinflInput,
} from '@akhatmirzo/ui';
```

Hammasi [MaskedInput](./masked-input.mdx) bilan bir xil qoidada ishlaydi: **ko'rinish —
formatlangan, qiymat — toza** (bo'sh joysiz). Tekshiruv `@akhatmirzo/core` dagi `isValidX`
funksiyalari bilan — [Identifikatorlar](../core/identifiers.mdx) sahifasiga qarang.

| Komponent          | Ko'rinish                | Qiymat (`value`)         |
| ------------------ | ------------------------ | ------------------------ |
| `PinflInput`       | 31503 90123 4567         | `"31503901234567"`       |
| `PassportInput`    | AA 1234567               | `"AA1234567"`            |
| `InnInput`         | 123 456 789              | `"123456789"`            |
| `CarPlateInput`    | 01 \| A 123 BC           | `"01A123BC"`             |
| `BankAccountInput` | 2020 8000 9000 1234 5001 | `"20208000900012345001"` |

## Qachon ishlatish

- **Davlat xizmatlari, bank, sug'urta, lizing formalari** — foydalanuvchi bo'sh joylarni o'zi
  qo'ymaydi, qiymat esa serverga tayyor holda keladi.
- **Har doim label bering** — [Field](./field.mdx) ichida. "JShShIR" yonida qayerdan topish
  mumkinligini `description` da yozing ("pasportdagi 14 raqamli shaxsiy raqam").
- **Xato sababini matn bilan ko'rsating** — komponent faqat `invalid` holatni qo'yadi,
  tushuntirishni `Field` ning `error` prop'iga yozing.
- **Hamma narsa `Input` dan meros:** `size`, `clearable`, `disabled`, `readOnly`, `name`.

## Tekshiruv

`validate` (standart `true`) — to'liq kiritilgan qiymat tekshiruvdan o'tmasa, maydon avtomatik
`invalid` bo'ladi. Yozish paytida qizarmaydi. Istisnolar: `InnInput` `0` bilan boshlansa va
`CarPlateInput` da hudud kodi ro'yxatda bo'lmasa — xato darhol ko'rinadi.

## PinflInput

JShShIR — 14 raqam, `5-5-4` guruhlar. 14-raqam kiritilganda `onDetails` chaqiriladi:
`{ valid, gender, birthDate, complete }` — jins va tug'ilgan sana raqamning o'zidan olinadi.
Nazorat raqami standartda tekshirilmaydi; `checksum` bilan yoqiladi.

<ComponentPreview name="document-inputs/pinfl" align="start" />

## PassportInput

Pasport yoki ID karta: 2 lotin harf + 7 raqam. Kichik harf avtomatik katta bo'ladi, kirill
harflar va ortiqcha belgilar qabul qilinmaydi. Mobilda klaviatura katta harf bilan ochiladi
(`autoCapitalize="characters"`).

## InnInput va BankAccountInput

STIR — 9 raqam (`000 000 000`), hisob raqami — 20 raqam, 4 tadan guruh. Ikkalasida ham mobilda
raqamli klaviatura ochiladi.

## CarPlateInput

Jismoniy (`01 A 123 BC`) yoki yuridik shaxs (`01 123 ABC`) formati 3-belgidan avtomatik
aniqlanadi: harf yozilsa — jismoniy, raqam — yuridik. Chapda hudud kodi ajratuvchi chiziq bilan,
o'ngda bayroq belgisi va "UZ" — haqiqiy raqam ko'rinishiga o'xshash.

<ComponentPreview name="document-inputs/car-plate" align="start" />

`onDetails` har o'zgarishda chaqiriladi — hudud birinchi ikki raqamdan, tur 3-belgidan keyin
ma'lum bo'ladi:

```tsx
<CarPlateInput
  onDetails={({ region, type, valid }) => {
    // region — UZ_REGIONS dagi obyekt yoki null; type — 'personal' | 'legal' | null
  }}
/>
```

Tafsilotlarni komponentdan tashqarida ham olasiz: `getCarPlateDetails('01A123BC')`,
`getPinflDetails('31503901234567')`.

## Accessibility

- **Native `<input type="text">`** — ekran o'quvchi formatlangan matnni o'qiydi.
- **Mobil klaviatura:** `PinflInput`, `InnInput`, `BankAccountInput` — `inputMode="numeric"`;
  `PassportInput` va `CarPlateInput` — `autoCapitalize="characters"`.
- **Xato holati** `aria-invalid` sifatida beriladi. Sababini `Field` ning `error` prop'ida matn
  bilan yozing — rang yagona signal bo'lmasin.
- **Dekorativ qismlar** — avtomobil raqamidagi ajratuvchi chiziq va bayroq belgisi
  `aria-hidden`; ekran o'quvchi faqat raqamni o'qiydi.
