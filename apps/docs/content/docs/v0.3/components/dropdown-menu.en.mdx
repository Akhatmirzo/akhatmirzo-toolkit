## Import

```tsx
import { DropdownMenu } from '@akhatmirzo/ui';
```

## When to use

- **Actions on a single object** — the "⋯" button in a table row, a card menu, a profile menu.
- **View options** — `CheckboxItem` (which columns to show) and `RadioGroup` (sort order).
- **Not for picking a form value.** For form fields use [`Select`](./select.mdx) or
  [`Combobox`](./combobox.mdx) — they hold the value and submit it with the form.
- **Destructive actions** (`variant="danger"`) go last, after a separator; confirm them with
  [`confirm()`](./dialog.mdx) when needed.
- **Keep submenus one level deep** — deeper nesting is awkward with a keyboard and on phones.

## Anatomy

| Part                                             | What it does                                                         |
| ------------------------------------------------ | -------------------------------------------------------------------- |
| `DropdownMenu`                                   | State: `open`, `defaultOpen`, `onOpenChange`                         |
| `DropdownMenu.Trigger`                           | Opens the menu. Without `asChild`, it looks like an `outline` button |
| `DropdownMenu.Content`                           | The panel: portal, positioning, looping navigation                   |
| `DropdownMenu.Item`                              | An action: `icon`, `shortcut`, `variant`, `onSelect`                 |
| `DropdownMenu.CheckboxItem`                      | A toggleable item (✓)                                                |
| `DropdownMenu.RadioGroup` / `RadioItem`          | One choice out of several (●)                                        |
| `DropdownMenu.Label`                             | A group heading                                                      |
| `DropdownMenu.Group`                             | Groups items logically                                               |
| `DropdownMenu.Separator`                         | A divider line                                                       |
| `DropdownMenu.Sub` / `SubTrigger` / `SubContent` | A submenu                                                            |

## Checkable items

`CheckboxItem` uses `checked` / `onCheckedChange`; `RadioGroup` uses `value` / `onValueChange`
(or an uncontrolled `defaultValue`). The menu closes after a pick; to let users toggle several
items in a row, call `e.preventDefault()` inside `onSelect`.

## Submenus

Put a `SubTrigger` and a `SubContent` inside `Sub`. The submenu opens on hover, or with `→` on the
keyboard.

## Profile menu: Label, Group and links

`Label` and `Group` split the menu into sections. Give an `Item` the `asChild` prop to render an
`<a>` (or a Next.js `Link`) as the item — the icon and the shortcut label are placed inside the
link. `align="end"` lines the panel up with the trigger's right edge.

<ComponentPreview name="archive/v0.3/dropdown-menu/profile" />

```tsx
<DropdownMenu.Item asChild icon={<Settings />}>
  <Link href="/settings">Settings</Link>
</DropdownMenu.Item>
```

<Callout title="shortcut is only a label">
  `shortcut={['mod', 'E']}` shows `⌘E` in the menu (`Ctrl E` on Windows) and sets
  `aria-keyshortcuts`, but it does **not** listen for the key press. Wire up the shortcut itself
  with [`useHotkeys`](../hooks.mdx).
</Callout>

## States

A `disabled` item can't be clicked and is skipped by keyboard navigation. The trigger can be
`disabled` too. Use `open` + `onOpenChange` to open the menu from code.

### Sub, SubTrigger, SubContent

`Sub` takes `open`, `defaultOpen` and `onOpenChange`. `SubTrigger` takes `icon` and `disabled`.
`SubContent` takes `sideOffset` (default `8`), `alignOffset` (`-6`), `collisionPadding` (`8`),
`loop` (`true`) and `container`.

### Data attributes

| Attribute          | On                 | Value                               |
| ------------------ | ------------------ | ----------------------------------- |
| `data-state`       | trigger, panel     | `open` · `closed`                   |
| `data-variant`     | item               | `default` · `danger`                |
| `data-highlighted` | item               | present under the keyboard or mouse |
| `data-disabled`    | item               | present when disabled               |
| `data-state`       | Checkbox/RadioItem | `checked` · `unchecked`             |
| `data-side`        | panel              | `top` · `right` · `bottom` · `left` |

## Keyboard

| Key                     | Action                                                   |
| ----------------------- | -------------------------------------------------------- |
| `Enter` / `Space` / `↓` | Opens the menu from the trigger, focusing the first item |
| `↓` / `↑`               | Moves between items (wraps around)                       |
| `Home` / `End`          | First / last item                                        |
| A letter                | Jumps to the next item starting with that letter         |
| `→` / `←`               | Opens / closes a submenu                                 |
| `Enter` / `Space`       | Selects and closes                                       |
| `Esc`                   | Closes; focus returns to the trigger                     |

## Accessibility

- **Roles.** The panel is `role="menu"`; items are `menuitem`, `menuitemcheckbox` or
  `menuitemradio`; the trigger gets `aria-haspopup="menu"` and `aria-expanded`. It is built on
  Radix DropdownMenu.
- **Shortcuts.** With `shortcut`, the item gets `aria-keyshortcuts` (`mod` becomes `Meta` on
  macOS and `Control` elsewhere). The visible `Kbd` is hidden from screen readers.
- **Icons** are `aria-hidden`.
- **Icon triggers.** When the trigger is an `IconButton`, give it an `aria-label` ("More
  actions").
- **Focus.** Opening moves focus into the menu; closing returns it to the trigger.
